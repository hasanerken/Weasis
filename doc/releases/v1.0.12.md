# v1.0.12 — Post Mortem Analysis

**Release Date:** 2026-03-03
**Type:** Bug Fix

---

## Why We Released

Duplicate anamnesis entries were appearing in the Anamnez panel when a patient had multiple HL7 orders, cluttering the UI and confusing clinicians.

---

## Problems

### 1. Duplicate Anamnesis Entries in the Anamnez Panel

**Symptom:** The same anamnesis text appeared multiple times in the Anamnez panel for a single patient. The number of duplicates corresponded to the number of HL7 orders associated with that patient.

**Root Cause:** The deduplication logic in `PatientCaseInfoPanel` built a key from the raw field values to detect and collapse identical entries. HL7 messages from different orders for the same patient often contained the same anamnesis text but with minor whitespace or line-ending differences (e.g., trailing spaces, `\r\n` vs `\n`). These were treated as distinct entries by the string comparison, so they passed through the dedup filter and all appeared in the panel.

**Fix:** Trim each anamnesis field individually before constructing the deduplication key, so whitespace/line-ending differences are normalized before comparison.

**Files Changed:**
- `weasis-dicom/weasis-dicom-explorer/src/main/java/org/weasis/dicom/explorer/PatientCaseInfoPanel.java`

---

## Lessons Learnt

1. **Normalize before comparing.** Any deduplication logic operating on text from external systems (HL7, DICOM, databases) must normalize whitespace before comparison. External systems rarely guarantee consistent whitespace handling.

2. **HL7 data is not clean.** Different HL7 senders (HIS, RIS, worklist servers) produce the same logical data with different formatting. Always treat external text as potentially dirty.
