# v1.0.11 — Post Mortem Analysis

**Release Date:** 2026-03-03
**Type:** Bug Fix

---

## Why We Released

Keyboard shortcut assignment was broken on Windows. Users could not assign bare (non-modifier) keys like `O`, `P`, `N` to actions in the ZenPACS shortcut preferences panel.

---

## Problems

### 1. Bare-Key Shortcuts Could Not Be Assigned on Windows

**Symptom:** In the ZenPACS shortcut preferences UI, clicking a shortcut field and pressing a bare key (e.g. `O` with no Ctrl/Shift/Alt) had no effect on Windows. The field did not update. The same action worked correctly on macOS.

**Root Cause:** The `JTextField` components in `ZenShortcutsPrefView` had `setEditable(false)` set to prevent the user from typing characters into them. On macOS, the custom `KeyAdapter` still received key events from a non-editable field. However, the Windows Look and Feel (`WindowsLookAndFeel`) does **not** deliver `keyPressed` events to non-editable `JTextField` components — only to editable ones. As a result, bare key presses were silently swallowed by the L&F before they reached the listener.

**Fix:** Set `setEditable(true)` on the shortcut fields to ensure the Windows L&F delivers key events. Add a `keyTyped` handler that calls `e.consume()` to prevent any characters from actually being inserted into the field. This preserves the intended behavior (no text input) while restoring key event delivery on Windows.

**Files Changed:**
- `weasis-dicom/weasis-dicom-explorer/src/main/java/org/weasis/dicom/explorer/pref/ZenShortcutsPrefView.java`

---

## Lessons Learnt

1. **Swing event delivery differs between Look and Feels.** What works on macOS's Aqua L&F may not work on Windows L&F. Key event delivery in particular has platform-specific behavior for non-editable components. Always test Swing keyboard handling on all target platforms.

2. **`setEditable(false)` is not equivalent to "read-only display" on all platforms.** It also affects event delivery, focus behavior, and rendering. Use `setEditable(true)` + `consume()` when you want a field that accepts focus and key events but does not accept typed text.
